# 标品商城后台管理系统产品文档规范

## Why

为标品商城后台管理系统提供完整的产品文档骨架，指导开发团队理解业务需求、功能模块划分、权限体系设计，确保系统开发有据可依。文档采用"功能模块+数据表字段"一体化组织方式，开发人员在完成模块功能学习后可立即查阅对应数据表结构，提高开发效率和数据模型理解连贯性。同时预留未来扩展空间，支持海外市场的国际化运营需求。

## What Changes

- 创建产品文档目录结构，包含六大功能模块文档
- 定义核心功能模块：
  - 注册用户管理（含用户表字段定义）
  - 商品SKU与库存管理（含商品表、SKU表字段定义）
  - 订单管理（含订单表字段定义）
  - 系统用户与权限管理
  - 多语言支持（面向海外市场的国际化支持）
  - 多货币管理（汇率管理与人民币金额计算）
- 建立系统角色定义与权限矩阵（5种角色）
- 设计各模块功能点清单、业务场景、状态流转
- 将数据表字段定义整合至对应功能模块末尾，实现"功能+数据"一体化
- 规划近期、中期、远期功能扩展路线图

## Impact

- Affected specs: 新建产品文档规范，定义六大功能模块需求
- Affected code: 后续将影响前端页面开发、后端API设计、数据库表结构设计
- Affected database: 用户表(users)、商品分类表(categories)、商品表(products)、SKU表(skus)、订单表(orders)、订单明细表(order_items)、汇率表、系统用户表(admin_users)、角色表(roles)、权限表(permissions)、用户角色关联表(user_roles)、角色权限关联表(role_permissions)等核心数据表
- Affected i18n: 多语言支持涉及语言包管理、商品多语言翻译、用户语言追踪
- Affected finance: 多货币管理涉及汇率系统、订单人民币金额计算、汇率快照机制

## ADDED Requirements

### Requirement: 产品文档目录结构

系统产品文档 SHALL 包含以下目录结构：

```
docs/
├── product/
│   ├── README.md                    # 文档概述
│   ├── 01-系统概述.md                # 系统背景与目标
│   ├── 02-角色权限.md                # 角色定义与权限矩阵
│   ├── 03-功能模块/
│   │   ├── 03.1-注册用户管理.md
│   │   ├── 03.2-商品SKU与库存管理.md
│   │   ├── 03.3-订单管理.md
│   │   ├── 03.4-系统用户与权限管理.md
│   │   ├── 03.5-多语言支持.md
│   │   └── 03.6-多货币管理.md
│   ├── 04-数据字典.md                # 核心数据字段定义
│   └── 05-扩展规划.md                # 未来功能扩展规划
```

### Requirement: 系统角色定义

系统 SHALL 支持以下角色：

| 角色    | 说明     | 权限范围           |
| ----- | ------ | -------------- |
| 超级管理员 | 系统最高权限 | 所有功能模块         |
| 运营管理员 | 日常运营管理 | 用户管理、商品管理、订单管理 |
| 客服人员  | 售后服务支持 | 订单查看、售后处理      |
| 财务人员  | 财务相关操作 | 订单查看、退款审核      |
| 仓库管理员 | 库存管理   | 商品库存管理、发货处理    |

### Requirement: 注册用户管理模块

系统 SHALL 提供注册用户管理功能：

#### 功能点清单

- 用户列表查询（支持搜索、筛选、分页）
- 用户详情查看
- 用户状态管理（启用/激活/禁用）
- 用户密码重置
- 用户信息编辑

#### 用户状态定义

| 状态  | 说明       | 可执行操作     |
| --- | -------- | --------- |
| 待激活 | 新注册未验证邮箱 | 发送激活邮件、禁用 |
| 已激活 | 正常使用中    | 禁用、重置密码   |
| 已禁用 | 账户被冻结    | 启用、重置密码   |

#### Scenario: 禁用用户

- **WHEN** 管理员点击"禁用"按钮
- **THEN** 用户状态变更为"已禁用"，用户无法登录系统

#### Scenario: 重置用户密码

- **WHEN** 管理员点击"重置密码"按钮
- **THEN** 系统生成临时密码并发送至用户邮箱

### Requirement: 商品SKU与库存管理模块

系统 SHALL 提供商品SKU与库存管理功能：

#### 功能点清单

- 商品分类管理（树形结构维护、增删改查、排序）
- 商品列表管理（增删改查）
- SKU规格管理（颜色、尺寸、内存大小等）
- 库存数量管理
- 库存预警设置
- 库存变动记录

#### 商品状态定义

| 状态  | 说明         |
| --- | ---------- |
| 草稿  | 商品创建中，不可上架 |
| 已上架 | 商品可被购买     |
| 已下架 | 商品不可购买     |
| 已售罄 | 库存为0       |

#### Scenario: 商品上架

- **WHEN** 商品信息完整且库存大于0
- **THEN** 商品状态变更为"已上架"，前端可展示

#### Scenario: 库存预警

- **WHEN** 商品库存低于预警阈值
- **THEN** 系统发送库存预警通知

#### 数据表字段定义

##### 商品分类表(categories)

| 字段名         | 类型           | 说明                     |
| ----------- | ------------ | ---------------------- |
| id          | bigint       | 主键                     |
| parent\_id  | bigint       | 父分类ID，顶级分类为NULL        |
| name        | varchar(100) | 分类名称                   |
| level       | tinyint      | 层级深度：1一级/2二级/3三级       |
| path        | varchar(255) | 分类路径，如"1,5,12"，便于查询祖先链 |
| sort\_order | int          | 排序序号，同层级内排序            |
| icon        | varchar(255) | 分类图标URL                |
| status      | tinyint      | 状态：0禁用/1启用             |
| created\_at | timestamp    | 创建时间                   |
| updated\_at | timestamp    | 更新时间                   |

**树形结构说明：**

- 采用"父ID + 层级 + 路径"组合方案，支持无限级分类
- `parent_id` 为 NULL 表示顶级分类
- `level` 字段便于快速筛选指定层级的分类
- `path` 字段存储从根到当前节点的ID路径，便于查询所有祖先或子孙节点
- 建议最大层级为3级（一级分类 → 二级分类 → 三级分类）

##### 商品表(products)

| 字段名          | 类型           | 说明                             |
| ------------ | ------------ | ------------------------------ |
| id           | bigint       | 主键                             |
| name         | varchar(200) | 商品名称                           |
| category\_id | bigint       | 分类ID，关联categories.id，通常关联最末级分类 |
| main\_image  | varchar(500) | 商品主图URL，用于列表展示                 |
| images       | json         | 商品多图URL数组，存储细节图、场景图等           |
| description  | text         | 商品描述                           |
| status       | tinyint      | 状态：0草稿/1上架/2下架                 |
| created\_at  | timestamp    | 创建时间                           |
| updated\_at  | timestamp    | 更新时间                           |

**关联说明：**

- `category_id` 外键关联 `categories.id`
- 商品应关联最末级分类（叶子节点），便于精准分类统计
- 创建商品前需确保分类数据已存在

**图片存储规范：**

- 存储方案：推荐使用CDN路径，格式为 `https://cdn.example.com/products/{product_id}/xxx.jpg`
- 支持格式：JPG、PNG、WebP（推荐WebP格式，体积更小）
- 主图尺寸：建议 800x800px，用于商品列表展示
- 多图尺寸：建议 1200x1200px 或 1200x1600px，用于商品详情页
- 多图数量：建议最多 9 张，包含细节图、场景图、包装图等
- 图片大小：单张图片不超过 2MB
- `images` 字段示例：`["url1", "url2", "url3"]`

##### SKU表(skus)

| 字段名                   | 类型            | 说明                    |
| --------------------- | ------------- | --------------------- |
| id                    | bigint        | 主键                    |
| product\_id           | bigint        | 商品ID                  |
| sku\_code             | varchar(50)   | SKU编码                 |
| specs                 | json          | 规格属性（颜色、内存大小等）        |
| image                 | varchar(500)  | SKU规格图URL，不同颜色/款式的展示图 |
| price                 | decimal(10,2) | 价格                    |
| stock                 | int           | 库存数量                  |
| low\_stock\_threshold | int           | 库存预警阈值                |

**SKU规格图说明：**

- 不同颜色/款式的SKU可设置独立的规格图
- 规格图尺寸：建议 400x400px，用于规格选择器展示
- 若未设置SKU规格图，则使用商品主图代替

### Requirement: 订单管理模块

系统 SHALL 提供订单全流程管理功能：

#### 功能点清单

- 订单列表查询（支持多条件筛选）
- 订单详情查看
- 订单发货处理
- 订单状态流转
- 售后申请处理（退款/退货）
- 物流信息管理

#### 订单状态定义

| 状态  | 说明         |
| --- | ---------- |
| 待付款 | 订单已创建，等待支付 |
| 待发货 | 已付款，等待发货   |
| 待收货 | 已发货，等待确认收货 |
| 已完成 | 交易完成       |
| 已取消 | 订单取消       |
| 售后中 | 存在进行中的售后申请 |

#### Scenario: 订单发货

- **WHEN** 管理员填写物流信息并确认发货
- **THEN** 订单状态变更为"待收货"，发送发货通知给用户

#### Scenario: 售后处理

- **WHEN** 用户提交售后申请
- **THEN** 创建售后工单，管理员审核后执行退款或退货流程

#### 数据表字段定义

##### 订单表(orders)

| 字段名            | 类型            | 说明                   |
| -------------- | ------------- | -------------------- |
| id             | bigint        | 主键                   |
| order\_no      | varchar(32)   | 订单号                  |
| user\_id       | bigint        | 用户ID                 |
| user\_language | varchar(10)   | 下单时用户语言，如zh-CN、en-US |
| currency       | varchar(10)   | 订单原币种，如CNY、USD、EUR   |
| total\_amount  | decimal(10,2) | 订单原币种金额              |
| exchange\_rate | decimal(18,6) | 下单时瞬时汇率（原币→CNY）      |
| cny\_amount    | decimal(10,2) | 订单人民币金额（汇率快照计算值）     |
| status         | tinyint       | 订单状态                 |
| shipping\_info | json          | 收货信息                 |
| created\_at    | timestamp     | 创建时间                 |
| paid\_at       | timestamp     | 支付时间                 |
| shipped\_at    | timestamp     | 发货时间                 |
| completed\_at  | timestamp     | 完成时间                 |

**多语言与多货币说明：**

- `user_language` 记录用户下单时使用的语言版本，用于后续多语言客服支持
- `currency` 记录订单原始币种，CNY表示人民币订单
- `exchange_rate` 为下单时刻的汇率快照，永久保存不受后续汇率变动影响
- `cny_amount` = `total_amount` × `exchange_rate`，用于财务统计
- 人民币订单：`currency` = CNY，`exchange_rate` = 1，`cny_amount` = `total_amount`

##### 订单明细表(order_items)

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | bigint | 主键 |
| order_id | bigint | 订单ID，关联orders.id |
| product_id | bigint | 商品ID，关联products.id |
| sku_id | bigint | SKU ID，关联skus.id |
| product_name | varchar(200) | 商品名称快照（下单时商品名称） |
| sku_specs | json | SKU规格快照（下单时规格属性，如颜色、内存） |
| quantity | int | 购买数量 |
| unit_price | decimal(10,2) | 商品单价（订单币种） |
| subtotal | decimal(10,2) | 小计金额 = unit_price × quantity |
| created_at | timestamp | 创建时间 |

**订单明细设计说明：**

- **商品快照机制**：`product_name`和`sku_specs`记录下单时的商品信息快照，不受后续商品信息变更影响
- **币种一致性**：明细金额与订单币种一致，统一在订单层面进行汇率换算
- **多语言支持**：`product_name`存储用户下单语言版本的商品名称，便于订单详情展示和售后处理
- **业务闭环**：
  - 订单详情查看：通过order_items关联查询商品信息
  - 售后退款：可精确到具体SKU进行退款处理
  - 销量统计：通过order_items聚合统计商品销量

**订单与明细关联关系：**

```
订单(orders) 1 ←→ N 订单明细(order_items)
订单明细(order_items) N ←→ 1 商品(products)
订单明细(order_items) N ←→ 1 SKU(skus)
```

**金额计算逻辑：**

1. 订单明细小计 = 单价 × 数量
2. 订单总额 = 所有明细小计之和
3. 订单人民币金额 = 订单总额 × 汇率快照

| real\_name  | varchar(50)  | 真实姓名       |
| status      | tinyint      | 状态：0禁用/1启用 |

##### 角色表(roles)

| 字段名         | 类型           | 说明                          |
| ----------- | ------------ | --------------------------- |

| status      | tinyint      | 状态：0禁用/1启用                  |
| created\_at | timestamp    | 创建时间                        |
| updated\_at | timestamp    | 更新时间                        |

##### 权限表(permissions)

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | bigint | 主键 |
| name | varchar(50) | 权限名称 |
| code | varchar(100) | 权限标识，如user:create、order:view |
| type | tinyint | 类型：1菜单/2按钮/3接口 |

**权限类型说明：**

- 菜单类型：用于前端菜单展示和路由控制
- 按钮类型：用于页面按钮级别的权限控制
- 接口类型：用于后端API接口权限校验

##### 用户角色关联表(user\_roles)

| 字段名         | 类型        | 说明                     |
| ----------- | --------- | ---------------------- |
| id          | bigint    | 主键                     |
| user\_id    | bigint    | 用户ID，关联admin\_users.id |
| role\_id    | bigint    | 角色ID，关联roles.id        |
| created\_at | timestamp | 创建时间                   |

##### 角色权限关联表(role\_permissions)

| 字段名            | 类型        | 说明                    |
| -------------- | --------- | --------------------- |
| id             | bigint    | 主键                    |
| role\_id       | bigint    | 角色ID，关联roles.id       |
| permission\_id | bigint    | 权限ID，关联permissions.id |
| created\_at    | timestamp | 创建时间                  |

**权限模型说明：**

- 采用RBAC（基于角色的访问控制）模型
- 用户通过关联角色获得权限，支持一个用户拥有多个角色
- 角色可关联多个权限，权限支持树形结构（菜单层级）
- 权限校验流程：用户 → 角色 → 权限

### Requirement: 多货币管理模块

系统 SHALL 提供完整的多货币管理与汇率功能，支持海外市场的多货币交易需求。

#### 多货币维护功能

系统 SHALL 提供多货币维护功能：

##### 功能点清单

- 多货币维护（添加、编辑、禁用）
- 货币基本信息管理（代码、符号、名称、小数位数）
- 货币启用/禁用状态管理

##### 货币状态定义

| 状态 | 说明       |
| -- | -------- |
| 启用 | 货币可用于交易  |
| 禁用 | 货币不可用于交易 |

##### Scenario: 添加新货币

- **WHEN** 超级管理员在货币管理页面添加新货币
- **THEN** 系统创建货币配置，支持设置货币代码、符号、小数位数等

#### 汇率管理功能

系统 SHALL 提供汇率管理功能：

##### 功能点清单

- 货币对汇率添加与管理
- 所有货币对与人民币(CNY)汇率对应关系
- 汇率数据存储（货币代码、汇率值、更新时间）
- 汇率CRUD操作接口
- 汇率管理（手动更新/自动获取）
- 第三方汇率API对接
- 汇率定时更新机制
- 货币操作日志记录

##### 汇率数据结构

| 字段名            | 类型            | 说明           |
| -------------- | ------------- | ------------ |
| id             | bigint        | 主键           |
| from\_currency | varchar(10)   | 源货币代码        |
| to\_currency   | varchar(10)   | 目标货币代码       |
| rate           | decimal(18,6) | 汇率值          |
| source         | varchar(50)   | 汇率来源（手动/API） |
| updated\_at    | timestamp     | 更新时间         |

##### Scenario: 添加货币对汇率

- **WHEN** 管理员添加新的货币对汇率

##### Scenario: 汇率更新

- **WHEN** 管理员手动更新汇率或系统自动获取汇率
- **THEN** 系统保存新汇率，记录汇率变更日志

##### Scenario: 汇率定时更新

- **WHEN** 系统到达定时更新时间点
- **THEN** 系统自动调用第三方API获取最新汇率并更新数据库
