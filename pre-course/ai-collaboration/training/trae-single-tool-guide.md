# 第一部分：Trae 工具认知篇

## 1.1 单一工具理念

### 传统多工具模式的问题

```
❌ 传统多工具协作模式：
┌─────────────────────────────────────────────────────────┐
│ Claude Code (架构师) → Trae (开发) → Code Buddy (测试) │
└─────────────────────────────────────────────────────────┘

问题：
- 工具切换繁琐，效率降低
- 上下文需要重复传递，容易丢失
- 学习成本高，需要掌握多个工具
- 配置复杂，环境搭建困难
- 协作流程冗长
```

### Trae 单一工具模式

```
✅ Trae 单一工具模式：
┌─────────────────────────────────────────────────────────┐
│                                                         │
│                    Trae IDE                            │
│                                                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐    │
│  │   架构师    │  │   开发者    │  │   测试工程师 │    │
│  │  角色能力   │  │  角色能力   │  │   角色能力   │    │
│  └─────────────┘  └─────────────┘  └─────────────┘    │
│                                                         │
└─────────────────────────────────────────────────────────┘

优势：
- 一个工具完成所有工作
- 上下文无缝传递
- 学习成本低，上手快
- 配置简单，一键启动
- 流程清晰，效率提升
```

### Trae 的多重角色能力

| 角色 | 能力 | 应用场景 |
|------|------|----------|
| **架构师** | 框架设计、技术选型、项目结构规划 | 初始化项目、设计系统架构 |
| **开发者** | 代码生成、组件开发、API实现 | 开发功能模块、编写业务逻辑 |
| **测试工程师** | 单元测试、集成测试、安全扫描 | 生成测试用例、执行测试 |
| **文档工程师** | API文档、注释生成、项目文档 | 编写接口文档、添加代码注释 |
| **运维工程师** | 部署配置、环境变量、CI/CD | 配置生产环境、编写部署脚本 |
| **代码审查员** | 规范检查、Bug发现、优化建议 | 代码Review、提出改进建议 |
| **Git 工程师** | 分支管理、提交审查、代码推送 | Git 操作、代码提交管理 |

```

│   │   │   ├── prd/         # 产品需求文档
│   │   │   ├── api/          # API文档
│   │   │   └── design/       # 设计稿
│   │   ├── db/               # 数据库脚本
│   │   └── tests/            # 测试代码

│
├── tools/                      # 开发工具
│   └── scripts/               # 脚本工具
│
└── shared/                     # 共享资源
    ├── docs/                  # 团队文档
    ├── scripts/               # 共享脚本
```

```
.trae/
├── specs/                      # 规格说明文档

├── documents/                  # AI生成的文档
├── workspace-rules.md          # 工作区规则
└── project-rules.md           # 项目规则
```

## 2.2 使用 Trae 初始化工作区

### 步骤 1：创建工作区目录

**Trae 操作**：
```
1. 打开 Trae IDE
2. 点击 "Open Folder" 或使用快捷键 Ctrl+O
3. 选择或创建工作区目录
```

### 步骤 2：让 Trae 创建项目结构

**提示词**：
```
请帮我初始化项目结构：

1. 在 projects/ 目录下创建新项目 MyProject
2. 创建标准目录结构：
   - frontend/ (前端代码)
   - backend/ (后端代码)
   - docs/ (项目文档)
   - db/ (数据库脚本)
   - tests/ (测试代码)

3. 在项目根目录创建：
   - .gitignore (Git忽略配置)
   - README.md (项目说明)
   - .env.example (环境变量模板)

4. 在 .trae/ 目录下创建项目规则文件
```

### 步骤 3：创建项目上下文

**提示词**：
```
请为 MyProject 创建完整的项目上下文文件：

1. 创建 .trae/project-rules.md，包含：
   - 技术栈说明
   - 代码规范
   - 命名规范
   - API规范

2. 创建 AGENTS.md，包含：
   - 项目简介
   - 开发流程
   - 团队规范

3. 创建 docs/README.md 作为项目文档入口
```

## 3.2 步骤详解

### 步骤 1：需求整理 → 产品文档

**原始需求示例**：
```markdown

用户管理系统

## 需求背景
需要开发一个简单的用户管理系统，支持：
1. 用户列表展示
2. 用户新增
3. 用户编辑
4. 用户删除
```

**Trae 提示词**：
```
请根据以下原始需求，生成一份完整的产品需求文档（PRD）：

要求：
1. 需求背景和目标
2. 用户角色定义
3. 功能模块详细设计
4. 页面交互说明
5. 接口需求
6. 非功能性需求

原始需求：
[粘贴原始需求内容]
```

### 步骤 2：产品文档 → 原型设计

**Trae 提示词**：
```
请根据产品文档，生成一个 HTML 原型页面：

要求：
1. 使用纯 HTML/CSS/JavaScript
2. 包含完整的页面布局
3. 模拟数据展示
4. 可交互的表格和弹窗
5. 响应式设计

产品文档内容：
[粘贴产品文档相关部分]
```

### 步骤 3：原型 → 前端代码

**⚠️ 重要：框架源码准备**

```
错误做法：
直接让 Trae 生成代码 → AI产生幻觉 → 生成错误代码 → 浪费时间

正确做法：
1. 准备好框架源码
2. 让 Trae 阅读框架核心文件
3. 理解框架的组件、API、规范
4. 再生成符合框架规范的代码
```

**Trae 提示词**：
```
请先阅读以下框架的核心文件，理解框架结构：

需要理解：
1. 组件使用方式
2. API调用规范
3. 状态管理模式
4. 路由配置方式

框架源码路径：[框架路径]

阅读完成后，请告诉我你理解了哪些关键点。
```

### 步骤 4：前端代码 → 后端 API

**Trae 提示词**：
```

要求：
1. 使用 PDO 连接数据库
2. 参数校验
3. SQL注入防护
4. 统一响应格式 { code, data, message }

前端API文件：[路径]
数据库配置：[配置文件路径]
```

## 3.3 代码生成最佳实践

### 提供清晰的上下文

**❌ 模糊提示词**：
```
帮我写一个用户管理模块
```

**✅ 清晰提示词**：
```
请帮我创建一个用户管理模块，包含：

1. 用户列表接口 GET /api/users
   - 支持分页
   - 支持按姓名搜索
   - 返回字段：id, name, email, created_at

2. 用户详情接口 GET /api/users/:id
   - 返回单个用户信息

3. 创建用户接口 POST /api/users
   - 请求参数：name, email, password
   - 密码需要加密存储

4. 更新用户接口 PUT /api/users/:id
   - 支持更新 name, email

5. 删除用户接口 DELETE /api/users/:id
   - 软删除

技术要求：
- PHP 8+
- 使用 PDO
- 遵循 PSR-12 规范
- 统一响应格式
```

### 分步骤执行

**Trae 提示词**：
```
请分步骤帮我开发用户管理模块：

第一步：创建数据库表结构
第二步：创建用户模型
第三步：创建用户控制器
第四步：添加路由配置
第五步：编写单元测试

每完成一步，请等待我确认后再进行下一步。
```
